# 嘉立创自动签到

嘉立创金豆每日自动签到插件，适配 AstrBot。

签到接口及 User-Agent 参考青龙项目；多账号指令、定时任务、结果推送和生命周期参考米游社插件。请求改为异步执行，无需安装青龙面板或配置其通知模块。

## 功能

- 私聊绑定 `X-JLC-AccessToken`，支持多个嘉立创账号、切换默认账号、更新 Token、解绑。
- 手动签到、自己的全部账号签到、管理员全员签到。
- 每日定时为所有绑定账号签到，完成后向各用户的绑定私聊会话推送结果。
- 查询实时金豆余额，兼容整数、小数及数字字符串，查看本插件的最近签到记录。
- 第七天奖励自动领取；已识别为第七天但领取失败时，当天重试会补领奖励。
- 网络异常、HTTP 429、服务端错误自动重试，账号间默认随机等待 5–15 秒。
- 固定使用北京时间（UTC+8），支持启动补签及配置时间变更，成功记录按账号保存。

## 安装

1. 使用 AstrBot 4.12 或更高版本，将本目录放入 `data/plugins/astrbot_plugin_autojlc/`。`main.py`、`jlc_client.py`、`storage.py`、`metadata.yaml`、`_conf_schema.json` 和 `requirements.txt` 应直接位于插件根目录。
2. 在 AstrBot 使用的 Python 环境安装依赖：`pip install -r data/plugins/astrbot_plugin_autojlc/requirements.txt`。使用插件管理器部署时可由管理器安装依赖。
3. 在 WebUI 重新加载插件，按需修改签到时间、结果推送等配置。
4. **私聊**机器人发送 `嘉立创 绑定 <Token>`，再发送 `嘉立创 签到` 测试。

## 获取 Token

1. 浏览器打开并登录 `https://m.jlc.com`。（注意该页面只有在移动端UA下才能正常打开，修改UA可以考虑使用`User-Agent Switcher and Manager`插件）
2. 按 F12 打开开发者工具，启用移动设备模式并刷新页面。
3. 进入个人中心、金豆或签到页面，在 Network 中查找 `selectPersonalAssetsInfo` 或 `signIn?source=3` 请求。
4. 在实际请求的 Request Headers 中复制 `X-JLC-AccessToken` 的**值**。
5. 私聊机器人：`嘉立创 绑定 <刚复制的值>`。

只复制原始 Token，不要包含请求头名称、引号、Cookie、`X-Xsrf-Token` 或多个逗号分隔的 Token。每个账号单独绑定。账号已有绑定时，重新绑定同一嘉立创账号会更新 Token，不会重复新增。

本插件使用上述参考项目提供的 Token 接口，暂不提供扫码登录。

## 指令

指令组 `嘉立创` 可替换为 `jlc`。按机器人唤醒配置，指令可能需要 `/` 前缀或 @ 机器人。

| 指令 | 说明 |
| --- | --- |
| `嘉立创 帮助` | 查看帮助和当前签到计划 |
| `嘉立创 绑定 <Token>` | 私聊验证并绑定账号，绑定后设为默认账号 |
| `嘉立创 签到` | 为自己的默认账号签到 |
| `嘉立创签到` / `jlc签到` | 默认账号签到的快捷指令 |
| `嘉立创 签到 全部` | 为自己的全部账号签到 |
| `嘉立创 查询` | 默认账号实时金豆余额及本地签到记录 |
| `嘉立创 我的` | 已绑定账号、默认账号、最近结果 |
| `嘉立创 切换 <序号>` | 切换自己的默认账号，从 1 开始 |
| `嘉立创 解绑` | 解绑默认账号，剩余账号的第一个成为默认账号 |
| `嘉立创 解绑 全部` | 解绑自己的全部账号 |
| `嘉立创 全部签到` | 仅 AstrBot 管理员：立即为所有用户的全部账号签到 |

除帮助和管理员全员签到外，指令均仅限私聊。全员签到指令只回复汇总，各用户的明细按推送配置发送到其绑定私聊。未注册通用的「签到」「打卡」快捷指令，可与米游社插件同时使用。

账号绑定按 AstrBot 平台实例 ID 和发送者 ID 隔离。主动推送使用绑定时的私聊会话；机器人平台必须支持该会话的主动消息。

## 配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `auto_sign` | `true` | 每日自动签到总开关，手动签到仍可用 |
| `sign_time` | `07:23` | 北京时间，24 小时制 `HH:MM` |
| `push_result` | `true` | 自动签到后私聊推送结果；也控制管理员全员签到的明细推送 |
| `catch_up` | `true` | 启动或变更计划后，补签当天已过计划时间且尚未成功的账号 |
| `api_retries` | `3` | 单个请求的最大尝试次数，含首次请求，范围 1–5 |
| `request_timeout` | `15` | 单次请求超时秒数，范围 3–120 |
| `account_delay_min` | `5` | 账号间随机等待的最短秒数，范围 0–300 |
| `account_delay_max` | `15` | 最长等待秒数，范围 0–300；上下界倒置时自动交换 |

插件每 30 秒检查内存中的配置变化；如果当前 AstrBot 版本通过重新加载插件应用 WebUI 配置，新实例会在初始化时直接应用。无效时间回退为 `07:23`。

自动任务只跳过**本插件记录当天成功**的账号；手动签到会实际调用接口，因此可核实外部已签到的情况。失败账号不记为当天成功，之后可以手动重试，或由重启补签、调整计划后的补签再次处理。插件不会全天轮询重试失败账号。

## 数据与结果说明

- 账号信息存放在 `StarTools.get_data_dir()` 返回的插件专属数据目录的 `users.json` 中，使用临时文件和原子替换写入。请备份该目录；更新插件代码不会主动清除绑定。
- Token 为完成自动签到所需的**明文敏感凭证**，不能视为加密存储。请保护数据目录及备份，绑定消息也可能被聊天平台和 AstrBot 的通用日志保留。
- 插件自有日志和结果不回显 Token，账号标识脱敏；不要额外启用会记录完整 HTTP 请求头的调试日志。数据文件损坏时插件会停止加载并保留原文件，避免覆盖。
- 普通签到的金豆余额按签到前资产余额与本次奖励计算；查询指令读取实时资产接口。第七天领取后重新查询资产，查询失败时只报告领取结果，不虚构余额或固定奖励数量。
- 查询展示的签到日期是本地成功记录，不能当作嘉立创服务端的实时签到状态；在其他客户端签到后，可手动执行本插件签到同步记录。
- 如果接口返回已签到但本插件没有当天的第七天待领奖励记录，不会盲目调用奖励接口。若服务端已处理请求但网络回执丢失，插件可能无法判断当天是否需要补领，请到官方页面核实。
- 退出登录或凭证到期可能导致 Token 失效，重新获取并绑定即可。推送失败不会重复签到，最近结果仍可在「嘉立创 我的」查看。

## 开发验证

在项目根目录安装运行依赖后执行：

```powershell
python -m unittest discover -s tests -v
```

测试使用模拟 HTTP 响应和 AstrBot 事件，不包含真实 Token，不会访问嘉立创签到接口。覆盖普通签到、已签到、第七天补领、异常响应、存储失败、账号管理、定时任务及推送隔离等流程。
